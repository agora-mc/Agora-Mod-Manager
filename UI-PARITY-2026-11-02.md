## The root cause, in one paragraph

The games side was built as independent slices under one rule from MASTER_SPEC §26.14: *"A slice replaces
its own component and never edits the shell."* Nobody owned the experience across slices, and no slice was
allowed to touch Minecraft's pages, so every slice rebuilt locally what Minecraft keeps inline in two giant
files (`pages/Instances.tsx` 1,636 lines, `pages/InstanceEditor.tsx` 4,088 lines). Minecraft's good parts
(card, hero, back button, empty state, skeleton, create-dialog form style) were never extracted into shared
components, so there was nothing to reuse. The fix is structural, not cosmetic: extract an "instance
experience kit" once, owned by one designer, and put both games on it.

## 3. Visual-flair gaps

1. **No hero anywhere on the games side** (`sk-01`, `sk-08`, `sk-09` vs `mc-01`). Every Minecraft page opens on
   the warm `.agora-hero` panel with an icon badge and chips; game pages start with bare text on the
   living background, so they read as a different, unfinished app. Biggest single visual difference.
2. **Cards have no hierarchy in their actions** (`pair-02-card`). Minecraft: filled Launch, outlined
   secondary actions, destructive Delete pushed right in red. Games: a filled "Open" carrying a **Play icon**
   (it does not play) next to a dark solid "Delete" of equal weight. Misleading and alarming at once.
3. **Identity**: every Skyrim tile is the same teal gradient with initials (hue comes only from the name);
   Minecraft tiles carry the loader hue, and the loader chip's dot matches it. The game's exe icon is
   already fetched for the switcher (`features/games/shared/icons.ts`) and unused here.
4. **Chips read as raw data**: "steam 1.6.1170" (lowercase store id), "Automatic", "Pinned base" all as
   equal muted chips. Minecraft gives the identity chip (loader) a coloured dot and keeps facts muted.
   Games should lead with a coloured store/version chip (Steam / GOG) and demote the rest.
5. **Status line**: seconds in the date ("12:30:00 PM"), no play time, no created date.
6. **Grid**: games `md:grid-cols-2`; Minecraft `auto-fill minmax(16rem)` scales with the window and text
   size (`--font-scale`).
7. **Header row** (`pair-04`): the games header is good (it was copied), but lacks the secondary-action
   cluster, the Rename affordance, the clickable image tile and the lock row, so the right half is empty
   and the card looks thin. The back control is a text link above it (note 4).
8. **Content tab** (`pair-05`): four bordered text buttons per row repeated down the page form a wall of
   identical controls; "On" is a tiny grey tag where Minecraft has a real switch; no table, no icons, no
   counts. Plugins tab is already a table, so the two sibling tabs disagree.
9. **Create dialog** (`pair-03`): wider (`max-w-2xl`), the placeholder renders at full contrast and is a long
   sentence, so it looks like a filled-in value; the selected base card is a darker grey rather than the
   accent ring; no "Recommended" marker; no autofocus ring on Name.
10. **Section headings** drift: `h2` at `text-base` (Content, Library), `text-lg` (Plugins, Tools, INI),
    `text-2xl` (Instances). Minecraft uses hero `h2` `text-2xl` and card `h3` `font-semibold`.
11. **Empty states**: games use a bare outline icon and one CTA; Minecraft uses the badge, more inviting
    copy and three CTAs (create, import file, import launcher).
12. **Settings** (`pair-06`): the game block pushes the rail below the fold, and the hero blurb still says
    "Everyday behaviour, the guided walkthrough, and application updates" above a Skyrim block.
13. **Switcher**: "Skyrim Specia…" truncates in the sidebar. A short name ("Skyrim SE") or a two-line
    entry with the exe icon would fix it.
14. **Motion**: `.instance-card:hover` lift and the running ring are shared CSS and already apply; skeleton
    shimmer and hero do not exist on the games side. No new motion is needed beyond adopting the shared pieces.

Fair to note: the games side is ahead in places: better `aria-current` on tabs, `ui/Button` instead of raw
classes, honest error states with "Try again", and the launch-check cards with "Why it matters / What to do".
Keep those.

## 4. The owner's six notes

### Note 1: per-game settings dumped above Settings
- **Cause**: `desktop/src/pages/Settings.tsx:2559-2582` renders a banner ("Showing settings for…") and
  `<GameSettingsSection>` **before** `<div className="settings-layout">` (`:2597`), outside the rail/sub-nav
  structure. `pages/settings/gameScope.ts:52-54` even classifies it as `'selected-game'`, "shown above the
  tabs". `GameSettingsSection.tsx` is one card holding four unrelated things (install folders, bases, three
  defaults, a link to Game support).
- **Fix**: delete the block. Add a game section to the `tabs` array (`Settings.tsx:2353`) that only exists
  while a non-Minecraft game is selected, in the rail slot Minecraft's "Launching" occupies (Launching is
  already hidden for other games by `gameScope`). Split `GameSettingsSection` into page-sized
  `SettingsSection` cards (section 5 wireframe). Move the "Showing settings for X / Switch to Minecraft"
  sentence into the hero as a chip. Extend `SettingsAudience` with `'other-games'` so every new card is
  classified and `gameScope.test.ts` keeps enforcing it.

### Note 2: "(recommended)" on the recommended options
- **Cause**: the copy has no notion of a recommendation. `features/games/instances/instanceText.ts:16-21`
  labels `auto` just "Automatic"; `baseModeCopy` (`:68-78`) labels "Linked base"; the dialog renders them at
  `CreateInstanceDialog.tsx:173-192` (cards) and `:196-212` (select); the Overview segmented control at
  `InstanceOverview.tsx:139-156`. Settings separately says "(default)" (`GameSettingsSection.tsx:33, 38, 45`).
- **Fix**: add `recommended: true` to the option data in `instanceText.ts` (`auto`, `linked`), and render it
  once through the shared `ChoiceCards` ("Recommended" badge on cards, " (recommended)" suffix in selects).
  Use the same source in Settings so the two never disagree. One push-back: keep "recommended" (what
  Agora advises) separate from "default" (what the user chose in Settings). If a user sets Copied as their
  default, the dialog should preselect Copied and still badge Linked as recommended. Today the dialog
  silently preselects the stored default with no marker either way.

### Note 3: card has only Open and Delete
- **Cause**: `features/games/instances/InstancesTab.tsx:180-195`. "Open" is a primary button with a Play
  icon; Delete is outline with no destructive tint and is not pushed right. Launch cannot live on the card
  because the launch flow (`launch`, VFS fallback question, refused reply, elapsed timer) is owned by
  `InstanceSessionProvider` (`instances/instanceSession.tsx`), mounted per instance page
  (`GameInstancePage.tsx:23`). The card also has no created date, no lock label and no readiness.
- **Fix**: (a) lift launching into a `GameLaunchProvider` mounted once around the game destinations, so a
  card and a page share the same in-flight launch; (b) rebuild the card on the shared `InstanceCardFrame` +
  `InstanceActionBar`: **Launch** (primary) / **Edit** / Clone / Group / Troubleshoot / Delete (right,
  destructive), showing only what the game supports today. Minimum for this note: Launch + Edit +
  Troubleshoot (opens Overview checks) + Delete; Clone, Group and Rename light up as their backend commands
  land (slice B1). When a launch from the card answers `refused` or `vfs_unavailable`, the card shows a
  compact banner with "Review" that opens the instance page where the full question already lives.
  `e2e/games-instances.spec.ts` clicks `{ name: 'Open' }` and must change with it.

### Note 4: "← Instances" is plain text
- **Cause**: `features/games/shell/GameInstancePage.tsx:24-31`, a `<button>` styled as an underlined text
  link. Minecraft's `BackButton` (`pages/InstanceEditor.tsx:4048-4057`) is a bordered button but private
  to that file.
- **Fix**: move `BackButton` to `components/ui/back-button.tsx` (optional `label`, default "Back"), import it
  in `InstanceEditor.tsx` (4 call sites) and in `GameInstancePage.tsx` as `← Instances`, placed on its own row
  like Minecraft's, with room for a right-aligned view toggle later.

### Note 5: example text unformatted and overflowing
- **Cause**: `features/games/instances/CreateInstanceDialog.tsx:141`:
  `` placeholder={`For example, ${gameName} with my mods`} `` produces "For example, The Elder Scrolls V:
  Skyrim Special Edition with my mods", longer than the field. The shared `components/ui/input.tsx`
  placeholder is plain `placeholder:text-muted-foreground`, which on the dark theme is close to the value
  colour (see `sk-03b`). Minecraft uses `placeholder="e.g. Optimized Survival"` with
  `placeholder:italic placeholder:text-muted-foreground/70` and a "Type a name to enable Create." hint
  (`pages/Instances.tsx:1383-1390`).
- **Fix**: short, game-flavoured examples ("e.g. Survival Requiem"), the `e.g.` form, and the italic /70
  placeholder. Put the placeholder style in the shared `Input` (it is the app's convention already, and
  Minecraft's raw inputs use it) so every form matches. Add the same disabled-reason hint. Narrow the
  dialog to `max-w-lg` and collapse Base + How it will run into an "Advanced" disclosure that defaults to
  the recommended choices (wireframe below).

### Note 6: reinvention, missing features, less flair
- **Cause**: see the root-cause paragraph. No shared instance components exist to reuse, and the slice rule
  forbade any slice from building them.
- **Fix**: sections 5 and 6. One designer builds the kit and the central pieces; slices adopt it.

## 5. The design: one instance experience, game-specific slots

### Principles
1. **Same frame, different organs.** Every game gets the same list page, card, create dialog frame,
   instance header, tab bar and settings structure. What differs is *data in slots*: chips, the create
   form's "what to build from" fields, the instance tabs, readiness source.
2. **Capabilities, not disabled buttons.** Each game exposes an `InstanceCapabilities` set (`launch`, `kill`,
   `rename`, `clone`, `group`, `lock`, `trash`, `notes`, `openFolder`, `image`, `export`, `playTime`,
   `troubleshoot`). The shared components render what is supported. Minecraft supports all of them;
   Skyrim gains them as backend commands land. No greyed-out "coming soon" clutter.
3. **Kit is presentational.** `components/instance-kit/` holds no IPC and no game knowledge; it takes props
   and slots. Minecraft and games adapters stay where they are (`pages/`, `features/games/`), which keeps
   `agora-core` the owner of behaviour and keeps the interactive-feature boundary untouched (nothing here
   lives in or imports `features/interactive/`).
4. **Minecraft is the reference, not the victim.** The kit is extracted from Minecraft's DOM and classes,
   so Minecraft can adopt it later without a visual change. Migrating Minecraft is optional and last.

### Shared kit (`desktop/src/components/instance-kit/`)
| Component | Replaces |
|---|---|
| `PageHero` | inline `.agora-hero` blocks; games' plain headers |
| `BackButton` (in `components/ui/`) | `InstanceEditor.tsx` private one; games text link |
| `InstanceCardFrame`, `InstanceActionBar`, `InstanceCardSkeleton` | games card; MC card's outer frame |
| `InstanceGrid` (groups, collapse, auto-fill grid, empty, loading) | the list layout in both |
| `EmptyState` | four or five hand-rolled empty states |
| `InstancePageHeader`, `ReadinessLine`, `InstanceTabBar` | `InstanceHero.tsx`; MC header markup |
| `CreateInstanceFrame`, `FormField`, `ChoiceCards` (+ `Recommended`) | both create dialogs' scaffolding |
| `types.ts`: `InstanceCapabilities`, `ReadinessView`, `InstanceAction` | – |

### Game-specific (stays in `features/games/**` or `pages/`)
Chips content; create-form body (MC: version, loader, memory, template; games: install, base, run mode);
instance tabs and their content (Plugins, INI & saves, Tools, FOMOD stay games-only); readiness mapping
(`HealthReport` vs `InstanceCheck`); launch controllers (MC `useProcessController`, games
`GameLaunchProvider`); Setup and Library pages.
